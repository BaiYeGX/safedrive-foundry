# G1-01 System contracts and runtime profiles

`sdf_interfaces` is the formal ROS 2 boundary. Every formal message embeds a
`RunIdentity` through `Frame`; its schema is `safedrive.runtime.v1`.

| Contract | Coordinate system / unit |
|---|---|
| Pose, twist, acceleration | CARLA/ROS map frame, right-handed ENU; m, rad, s |
| Actor dimensions | m |
| Trajectory time, speed, acceleration, curvature | s, m/s, m/s², 1/m |
| Steering and yaw rate | rad, rad/s |

`RunIdentity` is generated by the runtime from explicit experiment, scenario,
attempt and server-epoch inputs. It is deterministic across processes; a
changed attempt or server epoch creates a distinct run. G0's random
`episode_id` remains only in the JSON compatibility adapter and is never a
formal primary key.

The legacy `/safedrive/carla/status` JSON reader accepts only
`safedrive.carla.status.v2`, requires its compatibility `episode_id`, and
validates frame/time fields before returning a typed `StatusFrame`.

The runtime profiles are in `config/runtime_profiles.toml`: `throughput_20hz`
uses a 50 ms CARLA step; `control_50hz` uses a 20 ms step. Both enforce CARLA
substep capacity (`fixed_delta_seconds <= max_substep_delta_time * max_substeps`).
They are distinct measurement regimes: throughput results cannot be presented
as 20 ms control-deadline results.
